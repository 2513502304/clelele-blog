# 在网站管理个人资料与图片

登录站点 owner 的 GitHub 账号后，访问 `/admin`。管理页与 `/music/admin` 使用同一套身份校验，导航栏不显示入口；普通访客也看不到头像和横幅上的编辑按钮。

侧栏的显示名称、个人签名、联系方式，以及 About 页的“找到我”都读取同一份 HF 资料。联系方式可以增加、删除和调整顺序；保存后两处一起更新。About 的介绍正文和组件排版仍在仓库中编辑。站点标题、SEO 和作者署名属于网站配置，仍由 `config/site.yaml` 管理。

## 修改图片

管理页分别列出头像和各页面的横幅。未单独设置的页面沿用首页横幅；周刊保留原来的独立图片。点图片后，可以选择本地文件、粘贴剪贴板图片，或复用上传历史。

图片文件先保存到历史记录，选中的图片只是草稿。点击“保存并发布”并确认后，公开页面才会更换。上传和发布都有确认提示；有未保存修改时离开页面也会提示。图片选择窗口内部可独立滚动，背景页面保持锁定。

当前网页上传支持 JPEG、PNG、WebP、GIF，单文件最多 3 MB，以保持请求低于 Vercel 的请求体限制。系统保留原始字节，不偷偷缩小图片。历史选择器最多列出 500 个不同文件；达到上限后，新上传会移出最早且未被任何页面使用的历史记录，正在使用的图片始终保留。移出的只是选择器记录，HF 原文件不会删除。需要迁入更大原图时，使用本地初始化脚本或另行增加分块上传能力，不要靠提高前端限制绕过部署限制。

## 存储与一致性

HF 的 `site-profile/profile.v1.json` 是资料的唯一来源，图片位于同一命名空间的 `images/<sha256>.<extension>`。图片文件不可变；更换图片只更新资料中的引用。因此历史图片可以复用，也不会发生旧缓存拿到同名新文件的问题。

浏览器只拿到 `/api/site-assets/<slot>` 或经验证的图片 hash 地址。服务端返回短期签名重定向，HF 凭据不会进入网页。公开资料接口不返回历史记录；完整历史仅在管理员接口返回。头像和默认 OG 路径也已改为这一资源入口，不再从 `public/img` 读取。

保存使用资料 revision 与 HF ETag 双重校验。若另一个窗口已经修改资料，当前保存会返回冲突，不能静默覆盖。若写入后连接中断，服务端会回读 revision，确认写入是否已经成功。图片接口和资料接口有短缓存，公开页面更新通常需要约 30–60 秒。

## 配置与维护

沿用现有 `HF_S3_ACCESS_KEY_ID`、`HF_S3_SECRET_ACCESS_KEY`、GitHub OAuth 和 `STYLE_GALLERY_SESSION_SECRET`。owner ID 使用 `SITE_ADMIN_GITHUB_ID`，并兼容旧 `MUSIC_ADMIN_GITHUB_ID`。这次没有新增必须配置的生产密钥。`SITE_PROFILE_BUCKET_PREFIX` 可选，默认 `site-profile`。

`migrate-site-profile.ts` 只用于初始化空的 HF 命名空间。它读取显式的本地 seed JSON，先上传图片，再保存并回读资料。已有资料时直接退出，绝不把仓库的旧值重新覆盖到网站。执行方法见 `--help`。

当清理 Git 历史中的旧图片时，只处理已验证迁入 HF 的头像和横幅路径。先保存仓库 bundle，再在独立 mirror 中运行 `git-filter-repo`；不要在带未提交修改的工作目录直接重写。历史重写会改变 commit ID，必须与仍在使用旧历史的分支和部署协调。
