## 独立阶段的实测

最终配置用一张像素风模板和雷姆，安排两次 PixAI 任务。先清除图像供应商 key，只保留 DeepSeek key，运行 `--stage rewrite`：得到一次改写、可直接复制的 `prompt.txt` 和 `prompts.json`。随后清除文本供应商 key，只保留 PixAI key，运行 `--stage generate`：两次提交共用同一段文本，返回八张图片，每批有独立 ID 和回执。

上传阶段清除了全部文本、生图模型 key，仅使用已有的 HF 发布配置，八张图片全部发布。第一次上传中断后，续跑识别出已经完成的四张并跳过，只补上剩余四张；没有再次调用文本或生图 API。

GPT-6 Sol 验收 Agent 从 `/tmp` 调用全局技能入口，再次执行已完成的 generate 阶段。这次不提供任何模型 key，也省略 `--ledger`。脚本找到原账本，显示 28/400 次已用、零次新提交、两批已完成；前后账本和回执的 SHA-256 完全相同。

新配置还用真实 catalog 做过不收费的计划验证：三张卡片展开为四组模板/角色改写、五次生成任务，最多二十张图片。自动化测试覆盖了日期与稳定序号范围、模糊 hash、重叠选择、配置冲突、未知平台、预算不足及重复执行。范围结果会固定在 `plan.json` 中，不随网站后来新增的卡片变化。

纯文本任务可以省略生图 profile，也可标注 `external` 平台。Nano Banana、NovelAI 等未接入的平台不会阻塞 DeepSeek 改写与文本导出；这项能力不等于那些平台的生图 API 已验证。

## 视觉验收发现的限制

所有返回图片均作了视觉检查。流程可以无人值守执行，但画面质量仍会有偏差，不能用“API 成功”代替验收。

- 初版改写把花卉模板中的红色发饰带到其他角色身上。之后加强了“替换冲突发饰”的规则，但像素风秋山澪仍残留不属于角色设定的发夹。这类错误已出现在 DeepSeek 返回的文本中，不应全部归因于生图模型。
- PixAI 像素风样本经常增加标题、签名样字符，且未遵循闭眼要求。最终独立阶段的八张雷姆图片都出现了这两类偏差；其中一张还改变了双手姿态。两次重复生成确实产生不同图片，但随机性不保证每次都更符合要求。
- 少量其他 PixAI 图片也有签名样字符，夜景人物有遗漏发饰的情况。内置工具个别花卉或机甲图同样增加了未请求的文字。
- 内置工具生成的几何遮罩有马加奈图片，原本要求的薄荷绿背景变成了透明区域，60.34% 像素的 alpha 为零。保留原始 PNG 和这一失败记录，没有加工成符合要求的图片再称其成功。

因此，新模板族应先跑少量样本，检查角色特征、构图、文字和透明度，再决定是否扩大批次。当前不会因为视觉偏差自动重生成，也没有声称具备自动审美评分。完整输入、输出与偏差记录保留下来，便于以后改进文本模型或接入图像检查步骤。

## 保存、发布与可复现性

46 份成功回执包含原始模板、文本 API 请求/响应、生图请求/响应、实际提交的 prompt、任务 ID 和输出原图 SHA-256。内置工具返回的 base64 图片外置为原始文件，其余返回字段保留。失败或未知任务也保留本地账本与现有证据。

公开 sub-image 只承载展示字段和完整 note，供应商原始 metadata 放在私有 HF `generation-receipts/v1/` 下，既不公开密钥，也不让列表页加载大段响应。生成图片和本地回执在 Git 忽略目录中，不进入代码仓库。

127 张图片与 46 份私有回执已经发布并逐项回读通过。核对内容包括原图 SHA-256、完整 note、回执 JSON、来源卡片的图片与模板。花卉卡片原有的五张示例全部保留，加上本轮 58 张后共 63 张；其余四张卡片分别新增 27、15、14、13 张。结果记录在实验目录的 `publication-verification.json`。不同卡片共享 catalog，因此整个发布过程顺序执行。

技能按 `skill-creator` 的结构拆为入口、references、evals 和轻量 launcher，并用其 review viewer 汇集结果。最终入口经过真实子 Agent 和无 key 续跑验证。本轮没有重新运行付费的旧技能基线，因此不提供新旧版本成功率提升之类的比较数字。
