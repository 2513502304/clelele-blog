# Gallery 缩略图与 Lightbox 加载

列表显示缩略图，放大与下载仍使用原图。Sub-gallery 的 640px 是独立的 WebP 衍生文件，不是 HF 原图的尺寸限制。本次把未分组总览、详情页 sub-images 接到同一衍生图，并保留加载失败时的原图回退。

## 图片规格

| 入口 | 卡片图片 | Lightbox |
| --- | --- | --- |
| 风格提示词预览列表、图片矩阵 | 720px 宽参考图预览 | 原图 |
| Sub-gallery 开启分组 | 640px 宽 WebP 叠放预览 | 原图 |
| Sub-gallery 关闭分组 | 640px 宽 WebP 预览 | 原图 |
| 详情页 sub-images | 640px 宽 WebP 预览 | 原图 |
| 详情页参考主图 | 原图 | 原图 |

Sub-image 原图位于 `examples/images/<hash>.<ext>`，预览位于 `examples/thumbs/<hash>.webp`。预览保持比例，宽度上限 640px，不放大更小的图片，WebP quality 76。旧记录或外部图片不能推导衍生地址时，显示层直接保留原地址；上传和签名的严格路径校验不变。

## 只读采样

这些是当前网络下的单次诊断，未控制缓存、地区或连接复用，不是两个站点的严格性能排名。

| 样例 | 尺寸 / 字节 | 观察 |
| --- | --- | --- |
| HF 真实 sub-image 原图 | 1536×1024，1,036,146 bytes | WebP；对应预览独立存储 |
| 同一 sub-image 预览 | 640×427，31,932 bytes | 字节约减少 97%，源像素约减少 83% |
| PixAI artwork 2059122903663526986 的列表图 | 683×1024，58,372 bytes | `images-ng.pixai.art/images/thumb/...`，WebP |
| 同一 PixAI 图片的 orig 版本 | 800×1200，1,043,166 bytes | `images-ng.pixai.art/images/orig/...`，WebP，直接 CDN 请求 |
| Blog 参考原图 0abe9561f1c3 | 2805×4096，1,265,676 bytes | JPEG；前台 Edge fetch 首部约 1.66s，完整响应约 2.54s |

PixAI 打开图片后保留缩略图，原图就绪后再显示。其样例原图也约 1MB，并非所有延迟都能用文件大小解释。代理下独立请求样例的 thumbnail/orig 分别约 0.51s/1.73s，响应有明确的 `max-age=3600, stale-while-revalidate=604800`。

Blog 冷请求经过站点 302 → HF S3 302 → HF CDN。一次逐跳请求分别等待约 504ms、1027ms、648ms 首部，仅这条链路就约 2.18s。HF CDN 在该样例中未返回显式 Cache-Control，但这不等于浏览器一定不缓存。前台浏览器验证跨域 fetch 成功，因而保留原有真实字节进度；排除早先后台标签页暂停导致的异常耗时，不把它作为网络证据。

## 本次优化与边界

- 所有上述 sub-image 卡片复用既有缩略图，缓存身份与原图分开，图片比例、三行 prompt 内部滚动、点赞和下载行为不变。
- Lightbox 先显示已经加载的缩略图，完整图加载和解码完成后平滑替换；不会把缩略图下载为“原图”。
- 鼠标在明确的放大入口停留 250ms，或键盘聚焦入口后，低优先级预载该原图。移开、滚动、隐藏页面会取消尚未开始的悬停任务；键盘自动滚入视口不取消焦点意图。省流或 2G 网络不预载。单个在途意图任务，沿用已有去重和有界解码缓存，点击加入同一请求。
- 通过进度 fetch 下载的近期原图额外保留压缩 Blob：最多 6 张且总计 32MiB。关闭再打开可复用字节；每次 viewer 自己创建和释放 blob URL，图片解码失败会删除该缓存项。刷新页面不保留此内存缓存，签名 URL 变更不会错误复用旧地址。
- 首次未预热原图仍受 HF 重定向、网络和解码影响；这些改动不保证首次点击瞬间完成，也没有修改 HF 文件、降低原图质量或批量预载整页原图。

## 验证

浏览器测试覆盖两个入口的缩略图身份、原图逐步显示、无缓存响应的重复打开、缺失衍生图回退、键盘和悬停预载去重、滚动取消、省流模式，以及签名过期恢复。测试仅拦截 HTTP(S) 图片：WebKit 会拦截 blob URL，不能把测试用的外部图片屏蔽规则误用于本地已下载原图。

单元测试覆盖缩略图规格、旧路径回退、原图缓存数量/字节上限和精确 URL 身份。大数据 fixture 同时提供参考列表与 sub-image 索引，供真实渐进加载和返回滚动检查使用。

本轮结果：14 项 Chromium/WebKit 加载与签名路径、8 项 Chromium 大列表/分组路径通过；215 项单元测试通过。Astro check 为 0 errors、0 warnings，生产构建通过。Biome 仅保留未修改文件的已有 unused-import 提示；Knip 仍有 85 个未使用文件、12 个依赖、225 个导出等仓库已有问题。最初两个长列表失败来自单条 fixture，换成 672 条参考记录和 1344 条 sub-images 后，两个入口连续追加 12 批均通过。
